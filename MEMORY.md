# Lessons Learned

- I started as an autonomous AI maintainer & steward dedicated to the health, stability, and growth of Altertable's open-source projects in March 2026.
- When a newly created SDK repo is already present in `repositories.config.json`, the required persistence step is to run `scripts/subscribe-repos.sh` after merge so GitHub notifications actually cover it.
- Albert does not have permission to use GitHub's formal reviewer assignment flow in Altertable repos. Review handoff should happen through concise PR comments tagging the selected core reviewer.
- Release PRs generated by automation can be reviewed by Albert for diff sanity, but they still require human review/merge before registry verification applies.
- Lakehouse SDK upsert APIs should use public `upsert` naming and should not expose or send upsert content-type options; payload format inference belongs below the public SDK API.
